## Workflow

1. 깃허브 마일스톤과 지라 에픽을 생성 (서비스 별로)
2. 깃허브 이슈 생성 (생성할때 해당 마일스톤 태크를 추가)
3. 깃액션이 이슈생성을 감지하여 지라에 해당 에픽의 하위항목 태스크를 생성
4. 개발자가 지라에서 **“해야 할 일” 보드에 있는 작업에 해당하는 태스크** feature 브랜치를 생성
5. 깃액션이 브랜치 생성을 감지해서 지라에 해당 태스크 개발 시작 작업중으로 이동 (*슬랙알람)
6. 개발 완료 후 브랜치를 푸시
7. 개발자가 PR(풀리퀘) 생성 ()
8. 깃액션이 PR 생성을 감지하여 지라에 해당 태스크 칸반보드를 검토 중으로 이동 (*슬랙알람)
9. 관리자가 PR 머지를 진행 → 이슈가 자동으로 닫힘 (Closed #10)
10. 깃액션이 이슈가 닫힌것을 감지하여 지라에 해당 태스크 칸반보드를 완료로 이동 (*슬랙알람)

## Github 협업 정책

### 이슈 생성

- **라벨**을 반드시 설정해야 한다
- Jira의 epic과 일치하는 **마일스톤**을 반드시 설정해야 한다

### 브랜치

- Jira의 backlog에 있는 작업이 아닌 board로 옮겨져 **“해야 할 일” 보드에 올라온 작업**에 대해서만 브랜치 생성하기
- 브랜치명은 반드시 **Jira 티켓 번호**를 포함하고 있어야 한다
- 브랜치명 양식

### 커밋 메시지

- 커밋 메시지 종류
- 커밋 메시지 양식

### PR(Pull Request)

- PR 제목은 반드시 **Jira 티켓 번호**를 포함하고 있어야 한다
- PR 제목 양식
- PR 내용에는 아래의 내용을 반드시 포함시켜야 한다
    
    **“closed #[Github issue 번호]”**
    
    예시) closed #32
